# Feature Specification: AGY 委派可观察性与生命周期控制

**Feature Branch**: `003-agy-observability-control`

**Created**: 2026-11-09

**Status**: Draft

**Input**: 用户要求：相比官方 OAR 接 Codex/Claude，当前 AGY 接入还缺什么、可以补什么；重点是委派后无法确认 AGY 是否存活、卡住或已失败，父 Agent 可能永久空闲，且缺少主动查询、取消和安全的环境/诊断边界。

## 背景与问题

当前 `subagent_oar_agy` 能完成一次性委派并返回最终答复或失败通知，但父 Agent 在委派开始后只能等待：

- 如果 AGY 在启动阶段卡住，没有 `init` 事件，现有可选时限不会启动。
- 如果 AGY 已启动但长时间没有任何事件、也不退出，父 Agent 没有任何内部机制结束等待。
- 父会话只能看到“已开始”和最终通知；无法查询当前是启动中、运行中、已完成还是失败，也看不到最近活动。
- 取消只依赖中断父回合或关闭父会话，没有独立的取消入口。
- 子进程继承父进程环境，可能看到与任务无关的凭据形状变量和 DSH 内部变量。
- 父级诊断可能包含 stderr 摘要，缺少统一的脱敏与“原生细节只留本地日志”的边界。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 委派不会永久沉默 (Priority: P1)

用户把任务交给 AGY 后，如果 AGY 启动卡住或运行中长时间没有任何活动，系统必须在可配置的等待窗口内结束这次委派、终止对应进程，并向父会话发出可读的失败通知；父 Agent 不得无限空闲等待一个永远不会结束的委派。

**Why this priority**: 这是用户当前最直接的痛点。没有这一层，状态查询和取消都只是补救，父 Agent 仍可能永久沉睡。

**Independent Test**: 用一个不发送 `init`、不退出、也不产生结果的测试替身启动委派，确认在启动窗口结束后收到失败通知，且测试替身进程被终止；再用一个发送 `init` 后保持静默的替身，确认在静默窗口结束后收到失败通知。

**Acceptance Scenarios**:

1. **Given** AGY 进程已启动但始终不发送 `init`，**When** 启动等待窗口到期，**Then** 该次委派以失败结束，父会话收到可操作通知，AGY 进程及其工具子进程被终止。
2. **Given** AGY 已发送 `init`，但之后长时间没有文本、工具或状态事件且不退出，**When** 静默窗口到期，**Then** 该次委派以失败结束，父会话收到可操作通知，相关进程被终止。
3. **Given** AGY 在窗口内正常产生活动或正常结束，**When** 委派推进，**Then** 看门狗不得误杀任务，原有成功/失败/取消语义保持不变。

---

### User Story 2 - 能查询委派的当前状态 (Priority: P1)

用户在委派进行中或刚结束后，可以查询当前父会话所发起的 AGY 委派：它处于启动中、运行中、已完成、失败还是已取消；已经运行多久；最近一次活动是什么；当前步骤或工具是什么；是否已经卡住。查询不得创建、恢复或继续任何子任务。

**Why this priority**: 用户目前无法区分“在跑”“卡住”“已经死了”。状态查询是让父 Agent 或用户做出继续等待、取消或重试决定的基础。

**Independent Test**: 在启动中、运行中、成功后、失败后、取消后分别查询同一委派，确认状态、耗时、最近活动和终态与事实一致；查询不存在的委派或不属于当前父级的委派时返回明确的未找到/无权结果。

**Acceptance Scenarios**:

1. **Given** 一次委派处于运行中，**When** 用户或父 Agent 查询状态，**Then** 返回运行中状态、已运行时间、最近活动时间与类型、当前步骤/工具（若可得）以及子任务标识。
2. **Given** 一次委派已经完成、失败或取消，**When** 在保留期内查询，**Then** 返回对应终态、结束原因和最终耗时，不把已完成项误报为运行中。
3. **Given** 查询指定了一个不存在或属于其他父会话的委派，**When** 执行查询，**Then** 不泄露其他会话信息，并返回可理解的未找到或无权结果。
4. **Given** 父会话没有任何 AGY 委派，**When** 查询，**Then** 返回空列表而不是错误。

---

### User Story 3 - 能主动停止不需要的委派 (Priority: P2)

用户发现 AGY 任务方向错误、耗时过长或不再需要时，可以显式请求取消该次委派。取消请求本身立即得到受理反馈；实际停止和结果结算异步完成，最终父会话仍会收到停止或失败通知。重复取消、取消已结束任务和取消不存在的任务都必须是安全的。

**Why this priority**: 当前只能通过中断父回合或关闭父会话取消，粒度太粗；独立取消可以让用户保留父会话并继续其他工作。

**Independent Test**: 启动一个长时间运行的替身委派，显式取消，确认请求被受理、进程树被终止、父会话收到停止通知，再次取消不报错；对已成功结束的委派取消应是无害的 no-op。

**Acceptance Scenarios**:

1. **Given** 一次委派正在启动或运行，**When** 用户显式取消，**Then** 请求被受理，委派最终以已取消/停止结束，父会话收到通知，相关进程不残留。
2. **Given** 同一次委派已经被取消或已经结束，**When** 再次取消，**Then** 操作安全返回，不产生重复通知或异常。
3. **Given** 取消一个不存在或不属于当前父级的委派，**When** 执行取消，**Then** 拒绝且不泄露其他会话信息。

---

### User Story 4 - 环境与诊断不会越过安全边界 (Priority: P2)

AGY 子进程只应获得运行所需的最小环境和用户显式配置的环境覆盖，不应自动继承父进程中的凭据形状变量或 DSH 内部变量。父会话中的失败诊断只包含分类、可操作建议和不敏感的事实；原始 stderr、工具参数和路径细节只进入本机调试日志，并经过截断与脱敏。

**Why this priority**: 这是安全与隐私边界；一旦凭据进入第三方 CLI 或父会话转录，后续很难撤回。

**Independent Test**: 在父进程设置若干可识别的凭据形状变量和 `DSH_*` 变量，启动委派并检查子进程实际环境，确认这些变量不存在；显式配置的 `env` 仍可传入。再用包含敏感标记的 stderr 触发失败，确认父级诊断不含标记，本机日志有脱敏记录。

**Acceptance Scenarios**:

1. **Given** 父进程存在凭据形状变量和 `DSH_*` 变量，**When** 启动 AGY，**Then** 子进程环境中不出现这些变量；`PATH`、`HOME` 等运行必需变量仍可用。
2. **Given** 用户显式配置了某个环境变量，**When** 启动 AGY，**Then** 该变量按配置传入；显式 `null` 删除仍生效。
3. **Given** AGY 的 stderr 含敏感标记或原始路径，**When** 失败通知到达父会话，**Then** 父级诊断不包含原始标记；本机调试日志保留经过脱敏和截断的摘要。
4. **Given** 子进程认证依赖父环境中的某个变量，**When** 该变量未被显式配置，**Then** 系统给出可操作的认证/配置提示，而不是静默继承。

---

### User Story 5 - 运行活动可回看但受控 (Priority: P3)

用户或父 Agent 查询状态时，可以看到最近若干条活动摘要（事件类型、时间、步骤、工具名、少量文本），足以判断任务是否在推进；完整原生转录、工具参数和推理内容不进入父上下文，活动历史数量有上限，任务结束后按保留策略清理。

**Why this priority**: 仅有“运行中/最近活动时间”对排障仍偏少；但完整流式输出既无必要也会污染上下文，应作为受限的诊断能力。

**Independent Test**: 启动一个产生多步事件的替身委派，查询状态，确认返回最近活动摘要且数量不超过上限；任务结束后确认历史按保留策略清理，父上下文没有完整流式文本。

**Acceptance Scenarios**:

1. **Given** 委派产生多次步骤/工具活动，**When** 查询状态，**Then** 返回有限数量的最近活动摘要，顺序正确，包含时间与类型。
2. **Given** 委派已经结束并超过保留期，**When** 查询，**Then** 不再返回该运行，或只返回符合保留策略的终态摘要。
3. **Given** 父 Agent 从未查询状态，**When** 委派完成，**Then** 父上下文只增加官方完成通知，不增加完整活动流。

---

### Edge Cases

- AGY 可执行文件存在但启动后立即崩溃，或根本不能执行。
- AGY 启动后不发送 `init`，但也不退出。
- AGY 发送 `init` 后只产生部分文本，随后静默或退出。
- AGY 进程退出但没有 `result` 事件；退出码与 stderr 均可疑。
- AGY 输出非法 JSON、超大单行、持续 stderr 噪声或未知事件。
- 父会话在委派运行中取消父回合；以及用户显式取消后再关闭父会话。
- 取消发生在启动阶段：取消请求已受理，但启动中的原生会话可能还要一段时间才释放。
- 同一父会话并发多个委派，其中一个卡住、一个正常、一个已完成；状态查询和取消只影响目标。
- 查询/取消已结束、已清理、从未存在或属于其他父会话的委派。
- 父进程环境没有 `HOME`/`PATH` 等必需变量，或显式 env 覆盖了认证相关变量。
- 父会话或 Host 崩溃后重启；本 Feature 不承诺恢复已完成通知，但不得把旧运行误报为当前运行。
- 看门狗与正常完成、父级取消、显式取消同时发生时，只能产生一次终态和一次父级通知。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为每次委派提供可配置的启动等待窗口；从子进程启动到收到首个就绪事件超过窗口时，MUST 终止该委派及其进程树，以失败结算，并向父会话发送可操作通知。
- **FR-002**: 系统 MUST 为运行中的委派提供可配置的静默等待窗口；连续超过窗口没有任何来自 AGY 的活动事件且进程未结束时，MUST 终止该委派及其进程树，以失败结算，并向父会话发送可操作通知。本规格中的“活动事件”仅指已成功解析的 AGY 协议事件（`init`、`step_update`、`result`）和生命周期边沿（`init`、结算）；原始 stderr、非法 JSON 与普通日志不重置静默计时。
- **FR-003**: 系统 MUST 支持查询当前父会话发起的 AGY 委派状态，返回至少：子任务标识、状态、开始时间、已运行时间、最近活动时间与类型、当前步骤/工具（若可得）、终态与失败分类（若已结束）。
- **FR-004**: 状态查询 MUST NOT 创建、恢复、继续或改变任何委派；查询 MUST 只返回当前父会话有权查看的直接委派。
- **FR-005**: 状态查询 MUST 对不存在、已清理或属于其他父会话的委派返回明确的未找到/无权结果，不得泄露其他会话的存在或内容；当前父会话没有委派时 MUST 返回空结果。
- **FR-006**: 系统 MUST 支持对当前父会话的直接委派发起显式取消；取消请求 MUST 立即返回受理状态，实际停止与结算 MAY 异步完成。
- **FR-007**: 显式取消 MUST 幂等：重复取消、取消已结束或已取消的委派不得产生重复终态、重复通知或异常；取消不存在或无权委派 MUST 被拒绝。
- **FR-008**: 启动超时、静默超时、显式取消、父级取消和正常完成竞争时，系统 MUST 只结算一次终态，并只向父会话投递一次对应通知。多个看门狗同时到期时，绝对 `timeoutMs` 优先于静默窗口；已观察到的 `result` 优先于看门狗；其余情况取最早到期者，终态分类只记录胜出原因。父会话关闭沿用共享服务的一次性 dispose/终止语义，与显式取消区分；本 Feature 不承诺恢复。
- **FR-009**: 所有终止路径 MUST 终止 AGY 进程及其派生的工具子进程；终止失败 MUST 记录可诊断信息，但不得让父会话无限等待。
- **FR-010**: AGY 子进程 MUST 只继承运行必需的环境变量和用户显式配置的覆盖；凭据形状变量和 DSH 内部变量 MUST 在子进程启动前被移除，除非用户显式配置重新提供。
- **FR-011**: 父会话可见的失败诊断 MUST 只包含失败分类、阶段/可操作建议和不敏感事实；原始 stderr、工具参数、绝对路径和凭据 MUST NOT 进入父会话诊断。
- **FR-012**: 系统 MUST 提供本机调试记录能力，保存经过截断与脱敏的原始失败摘要，供用户排障；默认不得把该原始内容写入父会话或上传。
- **FR-013**: 系统 MUST 为每次委派保留有上限的最近活动摘要，供状态查询使用；摘要包含事件时间、类型、步骤/工具名和受控的文本片段，不包含完整推理或完整工具参数。
- **FR-014**: 已结束委派的活动摘要和状态 MUST 按有界保留策略清理；清理后不得把旧运行误报为当前运行，也不得无限占用内存。
- **FR-015**: 现有 `subagent_oar_agy` 委派入口的参数、返回值和一次性外部队列语义 MUST 保持不变；新增能力不得要求修改官方 OAR 工具 schema。
- **FR-016**: 新增的状态与取消能力 MUST 仅在插件启用时可用；禁用插件后不得留下可调用的工具或后台监控，且插件清理阶段 MUST 停止其计时器，并对该 provider 尚未结算的 AGY 运行执行终止；不得留下无监控进程。
- **FR-017**: 所有新增超时、保留和诊断行为 MUST 可配置或有明确默认值，并在文档中说明默认值、适用范围和调整方式；本 Feature 不提供看门狗关闭开关。
- **FR-018**: 现有成功、失败、认证失败、权限拒绝、父级取消和超时行为 MUST 保持兼容；现有测试与真实 AGY 冒烟 MUST 继续通过。

### Key Entities

- **委派运行**：一次 AGY 委派的身份与生命周期，包含子任务标识、父会话、状态、开始/结束时间、进程标识、原生会话标识、当前步骤/工具、最近活动、终态和失败分类。
- **活动摘要**：运行期间的一条受限观察记录，包含时间、事件类型、步骤序号、工具名、状态和截断文本；有数量上限和保留期限。
- **状态快照**：面向当前父会话的一次查询结果，包含一个或多个委派运行的当前状态与活动摘要，不包含完整流式输出。
- **取消请求**：针对某个直接委派的停止意图，包含目标标识、请求结果和最终结算状态。
- **看门狗配置**：启动等待窗口、静默等待窗口、活动历史上限和终态保留策略；有安全默认值，可显式调整。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在启动阶段完全不产生就绪事件的受控测试中，100% 的委派在启动等待窗口结束后 5 秒内以失败结算，父会话收到通知，且没有残留的 AGY 进程。
- **SC-002**: 在已就绪但持续静默的受控测试中，100% 的委派在静默等待窗口结束后 5 秒内以失败结算，父会话收到通知，且没有残留的 AGY 进程。
- **SC-003**: 对运行中、成功、失败、取消、启动中等状态进行查询，返回的状态、耗时和最近活动与测试事实一致；状态查询不改变任何委派，准确率达到 100%。
- **SC-004**: 对当前父会话的启动中/运行中直接委派执行取消，100% 的取消请求被受理，目标最终进入已取消/停止终态，进程树无残留；重复取消和取消已结束任务不得产生异常、重复终态或重复通知。
- **SC-005**: 在父环境注入可识别的凭据形状变量和 `DSH_*` 变量后启动委派，子进程环境中这些变量的出现次数为 0；显式配置的环境变量按预期出现。
- **SC-006**: 使用包含敏感标记的 stderr 触发失败，父会话诊断中敏感标记出现次数为 0，本机调试记录中包含脱敏后的摘要。
- **SC-007**: 状态查询返回的最近活动数量不超过配置上限；任务结束并超过保留期后不再返回该运行，父上下文不增加完整活动流。
- **SC-008**: 现有成功、失败、认证失败、权限拒绝、父级取消和超时测试全部通过；真实 AGY 委派至少一次成功，且父会话在完成后自动恢复。

## Assumptions

- 本 Feature 复用官方 OAR 工具作为模型入口；新增状态/取消能力以本插件自己的工具或等价用户界面提供，不修改官方工具的参数和返回结构。
- 状态查询和取消只针对当前父会话的直接委派；不提供跨父会话、跨进程或跨重启的全局管理。
- 本 Feature 不提供实时 token 流、完整原生转录、结构化输出、继续对话或恢复执行；这些仍属于外部一次性委派的范围之外。
- 本 Feature 不实现 DSH 核心 UI 的 external 子代理行改造；状态通过模型可调用的查询结果和/或本插件自己的展示提供，后续可单独做 UI Feature。
- 启动等待窗口和静默等待窗口有安全默认值；默认值在 plan 中确定并写入文档，用户可调整。绝对轮次时限 `timeoutMs` 继续作为可选上限保留。
- 活动历史数量上限和终态保留期限在 plan 中确定；默认必须有界，不能无限增长。
- 环境清洗采用与官方 DSH/OAR 相同的“先清理凭据形状变量与 `DSH_*`，再应用显式 env”原则；`HOME`、`PATH` 等运行必需变量保留。
- 父级诊断不包含原始 stderr；原始内容只写入本机调试日志（DSH Host 日志，不新增独立持久化文件），并做截断和脱敏；日志保留与访问由 DSH Host 负责。
